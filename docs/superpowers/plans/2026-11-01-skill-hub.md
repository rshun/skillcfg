# Skill Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建支持 Linux/macOS/Windows 桌面端与 CLI 的 Skill 管理工具，内置 Codex、Claude Code、Antigravity、Grok Build，并让普通新增 Agent 仅通过 JSON 档案接入。

**Architecture:** Rust 纯核心、目录 IO 引擎和宿主无关应用服务分层，CLI 与 Tauri 调用同一应用服务。四个内置档案与运行时用户 JSON 档案共用声明式注册表和目录解析器；前端和 CLI 动态列举档案。React 使用已确认的蓝白工作台设计，写入只接受后端一次性预览；目录事务明确部分成功与并发边界。

**Tech Stack:** 候选为 Rust、serde/serde_json/serde_yaml/toml_edit/thiserror/clap、React 19、TypeScript、Vite、Tauri 2；确切版本和新增依赖须在实施前获用户确认，不默认安装。

**Spec:** [完整设计方案](../specs/2026-11-01-skill-hub-design.md)

状态：可配置 Agent 档案版已归档；第一阶段 Tasks 1–3 实施与 GitHub 验证进行中。用户已明确当前五项 Rust 依赖全部在 GitHub 下载，本机不安装。后续 Tasks 4–12 尚未开始，不能因执行技能要求连续推进而扩大本轮范围。

## Global Constraints

- 每次预览后手动应用；禁止自动同步。保存、编辑、导入和启动均不自动分发。
- 内置四个 Agent 与用户 JSON 档案走相同注册表；AgentId 为校验字符串，不得固定为四项枚举。普通第五个 Agent 接入不得修改 Rust/TS 或重编译。
- Linux/macOS/Windows 均提供桌面端和 CLI；首版架构为 Windows/Linux x64、macOS arm64 与 x64，其他 CPU 不隐含承诺。
- 所有编译、cargo check/test/clippy、TypeScript/Vite 构建、浏览器回归和 Tauri 打包只在 GitHub Actions 的 GitHub-hosted runners 运行；本地不编译或安装构建依赖。
- 源包入口可以是符号链接或 junction；包内部链接、设备文件和其他特殊条目首版阻止导入/应用。
- 单文件 4 MiB，单包 16 MiB，最多 1,024 个文件/目录条目，相对深度不超过 16，单次预览原始内容总和不超过 64 MiB。
- 第一阶段实施补充：最多 4,096 个去重后的 Skill/Agent 配对；独立源树在预算预检通过后使用 Arc 共享。公开差异文本每侧最多 64 KiB、整份视图最多 1 MiB，按 UTF-8 字符边界截断并标记 truncated；原始包与执行计划不截断。大批次需分批，后续 UI/CLI 要解释这些上限。
- 一次性预览有效期 600 秒；取消、新预览、过期及任何确认尝试消费旧预览。
- 完整目录复制，原文和资源按字节保留；旧包通过归档移出加载目录，不自动永久删除。
- 先备份后覆盖；共享实际目录只备份和应用一次；不承诺跨多个目标的全局原子性。
- Rust 核心/CLI 至少 1.85，桌面至少 1.90；Node 最低版本在前置核实时固定，不猜测。
- 不在 master/main 修改项目，不新增/升级/安装未经批准的依赖，不执行删除或危险 Git 操作。
- 自动化仅使用隔离 HOME/APPDATA/项目与演示资料；不输出或上传真实凭据。
- 后续每阶段必须 commit/push 到授权开发分支并获得匹配最终 SHA 的 GitHub CI 证据；必要的阶段内测试快照与修复可提交。不得自动合并主干、打标签、发布或部署。
- 用户要求与红线优先于任务模板；锁文件恢复、覆盖与任何例外均不能被计划视作预授权。

5. 前端切换范围、项目、Agent 或编辑档案时，旧异步结果、旧选择和旧预览不能污染新上下文；由 Task 8/9/10 验证。

## 2. 跨任务接口约定

核心类型放 `skill-core/src/model.rs`；仅内部使用，禁止整体 Serialize 到 IPC：

```rust
pub struct AgentId(String); // 私有字段；只能通过校验构造，不能枚举具体 Agent
pub enum Scope { User, Project }
pub enum Platform { Windows, Macos, Linux }
pub struct PackageId(pub String);
pub struct SkillMetadata { pub name: String, pub description: String }
pub enum EntryKind { Directory, File { bytes: Vec<u8>, unix_executable: bool } }
pub struct TreeEntry { pub relative_path: String, pub kind: EntryKind }
pub struct PackageTree { pub entries: Vec<TreeEntry> } // 相对路径有序且唯一
pub struct LibraryPackage { pub id: PackageId, pub metadata: SkillMetadata, pub tree: PackageTree }
pub struct SelectionPair { pub package_id: PackageId, pub agent: AgentId }
pub enum ConflictDecision { Skip, Replace }
```

`AgentId::parse(value: &str) -> Result<AgentId, CoreError>` 只做通用词法校验，不包含内置 ID 集合；registry 再按来源校验用户 `custom.<slug>` 命名空间。普通代码不得按具体 ID switch。`AgentProfile` 的 schemaVersion/packageFormat/variants/defaultVariant/roots/probes 与设计 §4.1 一致，RootSpec 固定 rootId/platforms/scope/base/relative/discovery/role/read/write/priority，可选 appliesToVariants/readEvidence；省略 appliesToVariants=全部 variants，省略 readEvidence=always。

布尔探针只产生读取证据，不控制写根资格；false/unknown 仍保留潜在影响提示。写根由平台/范围/当前 variant 的静态唯一 write=true 根确定，且 write=true 必须 read=true。`ReaderExposure { agent_id, variant_id, root_id, evidence }` 用于 possibleReaders；共享影响合并全部已知 variants，不能只看当前选择。

`RegistrySnapshot { revision, profiles, approvals, selected_variants, root_overrides, probe_snapshots }` 是后端内部类型；revision 不使用不稳定哈希作为完整性凭据，确认时重新读取实际定义、授权与探针。加载状态是 Builtin/CustomPending/CustomEnabled/Disabled/Invalid，来源由加载位置决定，不信任外部 JSON 自报“内置”。

`TargetKey` 是规范化物理目标键，由 IO 生成。`TargetSnapshot` 包含 `key/path/tree: Option<PackageTree>/selected_agents/possible_readers`；`None` 表示原本不存在，空目录为 `Some(empty)`，必须区分。

`DistributionPlan` 含按 TargetKey 去重的 `DirectoryChange`、脱敏前的内部 diff、阻止与跳过原因。`DirectoryChange` 固定 `key/path/before: Option<PackageTree>/after: Option<PackageTree>`；after=None 只用于明确恢复“不存在”，由归档实现，不删除。

`LibraryRecord` 固定 id/current_revision/name/display_name/description/source_kind/source_agent/source_path/imported_at；库中的完整树保存在 `packages/<id>/revisions/<revision_id>/`。catalog 字段必须与引用版本的 SKILL.md 一致，否则阻止分发。`DistributionRecord` 保存 package_id/revision_id/name_at_write/scope/project/physical_path/operation_id/selected_profiles（agent_id、variant_id、profile_revision），供更名后的旧位置提示和按原路径恢复。

IO 的 `MutationPlan` 同时承载目录变更和少量 JSON 设置/索引文件的 `FileChange { path, before: Option<Vec<u8>>, after: Option<Vec<u8>> }`，所有路径都必须先通过注册根校验。after=None 仅用于明确恢复原先不存在的文件，通过归档实现；普通文件变更采用原子文件写。多个独立目录组按回执逐组执行，不能隐含全局事务。

`AppContext { scope, project_root: Option<PathBuf>, platform, registry: RegistrySnapshot }` 由后端构建和校验；前端只传作用域、有效 AgentId 和明确选定项目，不能伪造平台、授权结果或最终写入根。

公开 `PreviewDto` 只含 `previewId/expiresAt/groups/warnings/blocked`；group 含真实安全路径、selectedAgents、possibleReaders、changeType、fileDiffs 和 counts，绝不包含原始快照字节。`ReceiptDto` 含 operationId、backupLocation、outcomes，每项使用设计中的七类状态。

请求/查看类型在相应用例模块中定义，并以 contract fixtures 固定：

- `ImportRequest { library_path, source: Agent(AgentId) | Directory(PathBuf) }`；`ImportChoice { source_item_id, action: Skip | Add | Replace(PackageId) | KeepSeparate }`。
- `ImportScan { scan_id, expires_at, items }`，item 含后台扫描条目 ID、元数据、安全来源路径、文件清单和 issues，不含 raw bytes。
- `EditDocumentRequest { package_id, edit_token, document: String }`；`SafePackageView` 返回 revision_id、元数据、安全原文、文件清单、issues 和 edit_token。token 在后端绑定整个编辑基线；疑似敏感原文不返回可保存的掩码文本，改为禁止编辑并提示本地处理。
- `GuiSettings { version: 1, library_path, backup_path, default_scope, last_project_dir, agent_variants: BTreeMap<AgentId, String> }`；`SettingsRequest { expected_revision, settings: GuiSettings }`，基线变化拒绝保存。agent_variants 只能引用注册表内的合法 ID/variant；缺省用档案 defaultVariant，不改变目录授权。
- `HistoryItem { operation_id, kind, created_at, scope, project, outcomes, backup_location }`；安全错误一律 code/message，不包含 YAML 解析器原文。
- `ProfileChangeRequest { profile_json, expected_revision: Option<String>, local_root_overrides, enable_after_save }`；`AgentProfileView` 含 id/displayName/source/state/variants/currentVariant/安全根摘要/issues，不含可执行代码。
- `ProfilePreviewDto { preview_id, profile_id, resolved_roots, probe_paths, possible_readers, warnings, blocked }`，只解析和检查路径元数据，未经授权不扫描包或读取探针内容。
- `ProfileEnableRequest { agent_id, enabled, expected_revision }`；启用只接受与既有授权完整内容匹配的档案，新增/变更内容必须先 preview_agent_profile/commit_agent_profile。
- 上述 Rust 字段经 serde 统一映射 camelCase，enum 的 IPC 字面量在 fixture 中固定；原始内部树不实现 IPC 序列化。

| 可分发与人工验证 | 12 | 三平台桌面/CLI 制品、运行证据、说明与实际 Agent 核对 | A1–A20 |

### 每阶段必须完成的仓库与 CI 检查点

1. 进入阶段前检查当前开发分支、工作区与 upstream，按用户红线同步远端，不混入其他人的改动。
2. 当前阶段的测试/实现需要编译时，精确暂存经敏感检查的文件，commit/push 到授权开发分支，触发 GitHub Actions；不得在本机补跑 cargo/npm 编译。
3. 阶段内允许必要的红灯验证与修复提交。独立评审后的最终提交必须有匹配 SHA 的必需 CI 绿灯；改了代码/配置就验证新 SHA。
4. 更新 docs/PROGRESS.md 的阶段范围和证据入口，阶段报告列明分支、commit、CI 链接与平台结果。每阶段至少保留一份远端可审阅 commit，不把所有阶段攒成最终一次提交。
5. GitHub 不可用或必需任务失败时标记“等待 CI/修复”，不能宣称阶段完成，也不退回本地编译。发布、主干合并和真实用户配置应用仍不隐含授权。

阶段评审不通过时只修该阶段的问题，再进入依赖它的阶段。先完成上游接口与模型，不让多个实现同时发明 DTO。允许在接口冻结后分开进行无共享写入的 UI 与 CLI 工作，但必须由用户选定执行方式。

回退策略：代码使用新开发分支保留现状，不用 reset --hard/clean/rebase。文件内容通过已持久化备份与明确恢复预览回退，不删除数据；新版本与旧版本的 journal/catalog schema 不兼容时阻止自动回退。安装包回退不能代替数据恢复。
