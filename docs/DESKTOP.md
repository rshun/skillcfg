# 桌面工作台

工作台采用已确认的雾蓝色布局，提供“我的 Skills / Agents / 变更历史 / 软件设置”四页、明暗主题、窄窗口与 200% 浏览器缩放自适应布局。桌面适配 Linux x64、macOS arm64/x64、Windows x64；完整安装包、免安装归档与原生启动校验由 GitHub Actions 生成，宿主机操作与真实 Agent 加载核对见 [人工验收手册](MANUAL-VALIDATION.md)。

## 操作方式

1. 在 Agents 查看安装检测、声明的读取根、已有 Skill 和来源。来源为目录链接时同时显示原位置与实际位置。读取错误或损坏档案不会显示成空库。
2. 从本地目录或 Agent 导入完整包。扫描、同名处理、预览、确认后只保存到库，来源保留。
3. 编辑库中的 SKILL.md 原文。保存失败保留输入；保存成功只更新库。包内资源继续保留，改名后的旧位置在详情提示。
4. 在“我的 Skills”为每个 Skill 分别勾选 Agent。切换 Skill 保留其他配对，切库、范围、项目或更改档案清空配对及旧预览。
5. 预览显示实际物理目录、主动选择与可能额外读取的 Agent、文本前后内容、二进制大小和旧包归档影响。同名冲突默认跳过，更改处理方式会生成新的后端预览。
6. 核对后手动确认。预览有效期十分钟，每次确认尝试消费其 ID；执行时锁定上下文。逐组回执分别显示写入、未变、跳过、阻止、失败已恢复、需要恢复与审计失败，不推断 Agent 已加载。
7. 在“变更历史”查看备份与事务现场。恢复也要独立预览和确认；启动时遇到待恢复任务只提示，不自动重放或清理。

目录选择器取消不改变当前项目；未保存的设置、文档和档案关闭时需要确认。设置损坏时保留原文件，通过设置页提示处理，不创建空白设置覆盖。

## 新增 Agent

通过 Agents 的通用表单或 JSON 导入档案，声明各平台根、Variant、条件探针和本机目录覆盖。内置定义只读；本机目录与启用状态可配置。自定义 ID 使用 custom. 命名空间。

保存启用前会显示当前平台解析的根目录与条件探针，必须勾选确认。启用后仍需另行选 Skill、预览和应用。停用只取消后续目标资格，已分发文件保留，其他 Agent 可能继续读取共享根。普通 skill-md-v1 Agent 不需新增前端枚举或代码插件；新的包格式或协议能力仍可能需要开发。

## 构建与界面验证

- `.github/workflows/desktop.yml`：Node 24 按提交的 package-lock.json 安装、单元/契约测试、TypeScript/Vite 构建、真实 Chrome 交互与截图；四个平台运行原生 Tauri 桥接测试、check、Clippy 和 release 构建。
- UI-review 制品包含五个窗口宽度的库界面、暗色以及四页与预览截图。测试用内存 IPC 合成资料，不读取开发者的真实 Agent 目录。GitHub runner 安装系统中文字库，应用不依赖在线字体。
- `desktop-candidate-*` 制品为嵌入前端的原生可执行候选。Linux 需匹配 WebKitGTK 4.1 等系统运行库，Windows 需 WebView2，macOS 需系统 WebKit。它们不能替代安装包、签名、公证或最低系统版本验证。
- 本机不运行 npm/cargo、产品测试、浏览器或打包。锁文件、图标转换和所有系统构建依赖均在 GitHub runner 处理。
- 浏览器直接打开前端只进入醒目标示的演示环境，使用内存模拟；不能作为本机安装状态、写盘或实际 Agent 加载的证据。桌面 IPC 失败不会静默切到演示。

原生程序支持 `--home` 指向隔离的绝对目录供人工验收使用；不能在真实 HOME 制造故障。`.github/workflows/release.yml` 已在四个平台执行原生桌面进程启动 smoke（Linux 配合 `xvfb-run`）与零启动写入校验，但原生目录选择器的真实鼠标点击、图形安装包向导及真实 Agent 发现/加载（`A14`）仍按 [人工验收手册](MANUAL-VALIDATION.md) 逐项人工记录，不以桥接单元测试或无头启动冒充已完成人工验收。
